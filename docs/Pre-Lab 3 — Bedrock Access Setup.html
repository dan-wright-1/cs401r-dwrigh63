How Bedrock access works now

If a tutorial (or an older version of this document) tells you to open the Model access page and tick boxes, it's out of date. AWS retired that page in October 2025.

  • Every serverless model is enabled by default. Titan, Nova, Llama, Mistral, DeepSeek, and the rest have nothing to request.
  • Third-party models subscribe themselves the first time you call them. Bedrock creates the AWS Marketplace subscription in the background. For that to work, your IAM identity needs aws-marketplace:Subscribe, Unsubscribe, and ViewSubscriptions (an admin user already has them), and the account needs a valid payment method.
  • Anthropic models add one step: a one-time use-case form per account.

So a classmate who says "I just called Claude and it worked" is probably telling the truth. Their account was in good standing and the form was already on file, or they never needed it.

Step 1 — Run the verification script

Start here. Don't do any setup until you know what's actually broken.

python3 - <<'EOF'
import boto3, json, botocore
cfg = botocore.config.Config(retries={"max_attempts": 1})
rt = boto3.client("bedrock-runtime", region_name="us-east-1", config=cfg)

# Embeddings
try:
    r = rt.invoke_model(modelId="amazon.titan-embed-text-v2:0",
                        body=json.dumps({"inputText": "30 day return policy"}))
    dim = len(json.loads(r["body"].read())["embedding"])
    print(f"PASS  Titan embeddings        dim={dim}")
except Exception as e:
    print(f"FAIL  Titan embeddings        {type(e).__name__}: {str(e)[:120]}")

# Generation - note the inference profile ID, not the bare model ID
try:
    r = rt.converse(modelId="us.anthropic.claude-haiku-4-5-20251001-v1:0",
                    messages=[{"role": "user", "content": [{"text": "Reply with OK"}]}],
                    inferenceConfig={"maxTokens": 10})
    print(f"PASS  Claude Haiku 4.5        {r['output']['message']['content'][0]['text'].strip()!r}")
except Exception as e:
    print(f"FAIL  Claude Haiku 4.5        {type(e).__name__}: {str(e)[:120]}")
EOF

Two PASS lines means you're done. Save the output; it's your deliverable.

If either line fails, match the error below.

Step 2 — Fix what failed

ResourceNotFoundException: Model use case details have not been submitted

You haven't submitted the Anthropic use-case form yet. This blocks every Claude model and no other model. You can submit it either way:

Console: Bedrock console → Model catalog → select any Anthropic model → open it in the Playground. The form appears on first use.

Python:

import boto3, json
bedrock = boto3.client("bedrock", region_name="us-east-1")

form = {
    "companyName": "Brigham Young University",
    "companyWebsite": "https://cs.byu.edu",     # a GitHub or portfolio URL is fine
    "intendedUsers": "0",                        # 0=Internal, 1=External, 2=Both
    "industryOption": "Education",
    "otherIndustryOption": "Higher Education",
    "useCases": "University coursework: retrieval-augmented offer generation and a "
                "customer-service agent over synthetic retail data. No production traffic, "
                "no real personal data.",
}
bedrock.put_use_case_for_model_access(formData=json.dumps(form).encode())
bedrock.get_use_case_for_model_access()   # raises ResourceNotFoundException if it didn't register

Access is granted as soon as the form goes through, though AWS says the change can take up to 15 minutes to show up. Then re-run Step 1.

The CLI version (aws bedrock put-use-case-for-model-access) requires AWS CLI 2.27.42 or later. On older versions the subcommand simply isn't there, and you won't get an error explaining why. Run aws --version, or use the Python version above.

AccessDeniedException

The automatic Marketplace subscription failed. Usually your IAM identity is missing the three aws-marketplace:* permissions, or the account has no valid payment method. Fix whichever it is, wait two minutes, and re-run Step 1. It can take a couple of minutes after the fix before calls stop being denied.

ValidationException mentioning on-demand throughput

You used the bare model ID instead of the inference profile ID:

modelId = "anthropic.claude-haiku-4-5-20251001-v1:0"     # WRONG
modelId = "us.anthropic.claude-haiku-4-5-20251001-v1:0"  # RIGHT

Claude on Bedrock only runs through inference profiles. The us. prefix keeps inference inside US regions. A global. profile also exists, but for a retailer handling US customer data, us. is the right default, and you should be able to say why.

ThrottlingException: Too many tokens per day (or Too many requests) on the very first call

This is the one that justifies assigning the pre-lab early.

You haven't used anything. AWS puts initial limits on some newer accounts, and for Bedrock that can mean an effective quota of zero tokens per day. The error message makes it look like you ran out.

Three things to know:

  1. Waiting won't fix it. The limit doesn't reset into anything usable.
  2. Service Quotas may say you're fine. The per-minute quotas can show the full defaults (millions of tokens per minute) while the account is still blocked. The limit that's actually stopping you isn't in the Service Quotas listing, so the Step 1 script is the only reliable test.
  3. You can't raise it yourself. Open an AWS Support case: Account and billing → Service limit increase (or Account verification) → Bedrock. Say that your first-ever Bedrock call returns ThrottlingException: Too many tokens per day, that you haven't used any quota, and that you're asking AWS to lift the initial limits on the account. Include your account ID, region (us-east-1), and the exact error text.

Tell the instructor the day you open the case, and give the case ID. We're tracking how long these take.

Cost

Bedrock charges per token and nothing while idle. Unlike a NAT Gateway or a SageMaker endpoint, nothing bills when you aren't calling it.

Realistic Track B usage is a few dozen embedding runs over the corpus plus a few hundred generation calls for RAGAS evaluation, which comes to well under $2. Track C is similar. Bedrock has no teardown step because nothing is left running.
