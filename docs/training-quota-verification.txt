Note: the evidence here conflicts. get-service-quota reports 0 applied, but a
request for 1 was rejected with:
  IllegalArgumentException: You must provide a quota value greater than the
  default quota value of 4.0
so the request API treats 4 as this account's baseline. I have not assumed
either value; the fallback is verified by launching a spot job (see below).

== Justification ==

I requested 2 concurrent on-demand ml.m5.large training instances. Lab 4's
pipeline runs one training job at a time, so 1 is the true minimum; 2 lets a
job keep running (or fail and hang) while I start a corrected run, without
asking for capacity I can't justify. A quota costs nothing on its own, and
training jobs terminate when they finish, so the extra instance only bills if
I actually use it. If the request isn't approved before Lab 4 opens on Oct 15,
my fallback is managed spot training on ml.m5.large (L-29688C85), with
checkpointing and a max-wait so an interruption retries instead of failing
the pipeline. The job trains in under two minutes on 10,000 rows, so
interruption risk is low. Because the applied spot quota reads 0 while AWS
treats 4 as the baseline, I will confirm the fallback with one short spot
training job before relying on it, and request 5 (the smallest value AWS
accepts) if that job hits ResourceLimitExceeded.
